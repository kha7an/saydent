# SayDent

Сайт и сервер приёма заявок с уведомлениями администратору через MAX.
Python 3.10+ без внешних зависимостей; SQLite находится в `data/`, токен используется только сервером.

## Подключение MAX

1. Создайте бота в MAX для бизнеса: https://business.max.ru/.
   Скопируйте его токен в серверную переменную `MAX_BOT_TOKEN`. Не добавляйте токен в HTML/JS или git.
2. Добавьте бота в закрытый чат сотрудников с правом отправки сообщений.
   Для нового подключения получите числовой `chat_id` из события `bot_added`,
   сверив время добавления и выбранный чат. При настроенном webhook событие приходит
   в существующий обработчик. Без webhook используйте `GET /updates`.
   Имя бота и ИНН клиники не определяют получателя. [Инструкция MAX](https://dev.max.ru/docs-api/use-cases/getting-chat-id/)

3. Скопируйте `.env.example` в `.env`, заполните токен, ID чата и `PUBLIC_ORIGIN`.
   Формат origin: `https://example.ru`, без пути и завершающего `/`.
   Для локальной проверки: `http://127.0.0.1:8765`.
   Значения в `.env` должны быть допустимы для shell; при необходимости заключайте их в кавычки.
4. Загрузите окружение и запустите **один** процесс:

   ```sh
   set -a
   . ./.env
   set +a
   python3 server.py
   ```

5. Откройте сайт по настроенному origin и отправьте тестовую заявку.
   В MAX должны прийти имя, телефон, время и номер заявки. Удалите тестовые данные из SQLite и MAX.

API: https://dev.max.ru/docs-api/methods/POST/messages/.
Используется `platform-api2.max.ru`, заголовок `Authorization` и проверка подтверждённого сообщения.
Для соединения с MAX сервер использует системные доверенные центры и корневой сертификат
НУЦ Минцифры из `deploy/russian-trusted-root-ca.pem`. Включите этот файл в поставку сервера.
Источник для сверки и обновлений — [Госуслуги](https://www.gosuslugi.ru/crt).

## Поведение формы

- Браузер отправляет `POST /api/appointments`: `request_id`, `name`, `phone`, `consent: true`,
  `consent_version: "2026-11-18"`. Сервер проверяет поля, согласие, origin и размер JSON (до 4096 байт).
- Успех означает сохранение заявки в SQLite, а время приёма подтверждает администратор.
  Форма показывает ожидание, блокирует повторный клик и сохраняет поля при ошибке.
- Повтор того же запроса с тем же ID не создаёт новую заявку. Другой ID с тем же телефоном
  ограничен на 10 минут; общий лимит — 20 новых заявок в минуту.
- Уведомления отправляет один фоновый поток. При сбое MAX повтор начинается через 30 секунд,
  затем интервал увеличивается до часа. Очередь переживает перезапуск сервера.
- Доставка имеет семантику «как минимум один раз»: если MAX получил сообщение, но ответ потерян,
  возможен повтор уведомления с тем же номером заявки. Это одна заявка, не две записи пациента.
- Заявки, включая недоставленные, удаляются через 30 дней работающим сервером.
  Если сервер был выключен, очистка происходит после запуска. SQLite использует secure_delete.
  Очистка сообщений MAX и резервных копий в тот же срок — обязанность ответственного клиники.
- Cookie `saydent_submitted` ограничивает повтор в браузере на 10 минут;
  `saydent_cookie_notice` запоминает закрытие уведомления на 180 дней. Контактов в cookie нет.
- Без JavaScript доступен телефон клиники, отправки формы нет.

## Размещение

Сервер слушает только `127.0.0.1:8765` (порт меняется через `PORT`). Внешний HTTPS reverse proxy
должен передавать сайт и `/api/appointments` в этот процесс, сохраняя заголовок `Origin`.
Готовый шаблон `deploy/nginx.conf` включает HTTPS, лимиты по IP (1 заявка/минуту с коротким всплеском до 3) и ограничение соединений. Включите файл в контекст `http {}` nginx, замените домен и пути сертификатов, задайте тот же домен в `PUBLIC_ORIGIN`, затем выполните `nginx -t` и перезагрузите nginx. Шаблон рассчитан на прямой доступ к nginx; за CDN сначала настройте доверенные адреса real_ip, иначе лимит будет общим для посетителей CDN. Origin защищает от межсайтовых запросов браузера, но не заменяет защиту от ботов. Настройте запуск Python через менеджер процессов:
встроенный HTTP-сервер предназначен для небольшого сайта за proxy, не для прямого доступа из интернета.
Отключите запись тела POST и параметров URL в логи proxy. Не кешируйте `/api/`.

`DATABASE_PATH` задаёт постоянный путь БД. Не используйте временный диск контейнера.
Размещайте данные на российском хостинге с ограниченным доступом и резервным копированием.
Новые файлы процесса создаются с закрытыми правами (`umask 077`); права уже существующей БД
и резервных копий проверяет администратор. Не запускайте несколько серверов/worker для одной БД.

Для контроля очереди выполните на сервере после загрузки окружения:

```sh
sqlite3 -readonly "$DATABASE_PATH" "SELECT count(*) AS pending, datetime(min(created),'unixepoch') AS oldest_utc FROM appointments WHERE sent IS NULL;"
```

При росте очереди проверьте доступность MAX, права бота и ошибки доставки в журнале процесса. При восстановлении связи процесс повторяет доставку сам.

Обработчик раздаёт только публичные HTML/CSS/JS и изображения, блокирует `.git`, `.env`,
README, тесты и БД. Если статику раздаёт сам proxy, публикуйте только `index.html`, `privacy.html`,
`consent.html`, `style.css`, `script.js`, `saydent-license.pdf`, `images/`; не раздавайте корень репозитория целиком.
Простой `python3 -m http.server` годится только для просмотра: API в нём отсутствует.

## Перед приёмом реальных заявок

В форме предусмотрено отдельное согласие. Сервер связывает дату и версию согласия с принятой заявкой. При смене редакции сохраните предыдущий HTML в закрытом каталоге `deploy/consents/` и обновите версию одновременно в форме и на сервере. Страницы согласия и политики доступны посетителю без JavaScript. Карта открывается только по ссылке. Аналитические и рекламные скрипты отсутствуют.

До запуска ответственному за персональные данные в клинике нужно сверить фактическую обработку с документами сайта:

- Проверить уведомление Роскомнадзора по ООО «САЙДЕНТ» и охват цели обратного звонка. При необходимости подать уведомление до начала обработки или обновить сведения действующего оператора. [Реестр Роскомнадзора](https://pd.rkn.gov.ru/operators-registry/operators-list/)
- Подтвердить расположение базы и копий в России, условия обработки у хостинга и в MAX, основание передачи, состав закрытого чата и порядок отзыва доступа. Проверить договоры и оформить поручения обработки там, где поставщик действует по поручению клиники. [152-ФЗ, ст. 6, 9, 18, 18.1, 19 и 22](https://mintrud.gov.ru/docs/laws/130)
- Утвердить срок хранения до 30 дней. Проверить досрочное прекращение при достижении цели или отзыве, уничтожение записей, сообщений и данных в копиях, фиксацию уничтожения и порядок уведомления при инциденте. Очистка SQLite работает при запущенном сервере. Удаление из MAX и из резервных копий требует отдельной процедуры клиники.
- Убедиться, что ответственный получает письма на `saydentkzn@mail.ru` и обращения по юридическому адресу. Для проверки использовать синтетическое обращение по согласованию с получателем.
- До публикации предоставить утверждённый график работы и приёма специалистов, сведения об образовании и квалификации, условиях оказания и оплаты услуг, подписанный прайс. Сверить применимые сведения для пациентов по действующим правилам платных услуг. [Правила платных медицинских услуг с 1 сентября 2026 года](https://13.rospotrebnadzor.ru/content/s-1-sentyabrya-2026-goda-vstupayut-v-silu-novye-pravila-predostavleniya-platnyh-medicinskih)

На 18.11.2026 реквизиты оператора и сведения о лицензии на главной странице сверены по выписке ЕГРЮЛ ФНС № ЮЭ9965-26-244615672 (ИНН 1655512315). Статус, адрес кабинета и перечень работ сверены с выпиской из реестра лицензий от 18.11.2026 14:44. Ссылка в футере взята из QR-кода этой выписки. Проверить повторно можно в [ЕГРЮЛ ФНС](https://egrul.nalog.ru/) и [реестре лицензий Росздравнадзора](https://roszdravnadzor.gov.ru/services/licenses).

Проверьте в целевом окружении: успешную заявку и сообщение MAX, сбой MAX и повтор после
перезапуска, повтор POST после потери ответа, запрет доступа к секретам, HTTPS и удаление данных.
Без реальных токена/чата проверяется только работа с имитацией API MAX.

## Проверки

```sh
node --check script.js
python3 -m unittest discover -s tests
```

Тесты проверяют HTTP-вход, валидацию, дубли, ограничения, закрытые файлы, хранение,
повтор уведомления и ошибки MAX (с подменой сетевого вызова), состояния формы и целостность страниц.
